# onchainos CLI 参数面（自动抓取；基准版本: onchainos 4.6.3）

## onchainos agent create-task
```
Create a new task (Client)

Usage: onchainos.EXE agent create-task [OPTIONS] --title <TITLE> --description <DESCRIPTION> --provider-agent-id <PROVIDER_AGENT_ID> --payment-token-symbol <PAYMENT_TOKEN_SYMBOL> --payment-token-amount <PAYMENT_TOKEN_AMOUNT> --service-id <SERVICE_ID> --service-token-address <SERVICE_TOKEN_ADDRESS> --service-token-amount <SERVICE_TOKEN_AMOUNT>

Options:
      --title <TITLE>
          
      --chain <CHAIN>
          Chain: ethereum, solana, base, bsc, polygon, arbitrum, sui, etc
      --description <DESCRIPTION>
          
      --description-summary <DESCRIPTION_SUMMARY>
          
      --provider-agent-id <PROVIDER_AGENT_ID>
          
      --payment-token-symbol <PAYMENT_TOKEN_SYMBOL>
          
      --payment-token-amount <PAYMENT_TOKEN_AMOUNT>
          
      --file <ATTACHMENTS>
          Local file paths to attach to the task after creation
      --service-id <SERVICE_ID>
          
      --service-params <SERVICE_PARAMS>
          [default: {}]
      --service-token-address <SERVICE_TOKEN_ADDRESS>
          
      --service-token-amount <SERVICE_TOKEN_AMOUNT>
          
      --category-code <CATEGORY_CODE>
          
      --min-credit-score <MIN_CREDIT_SCORE>
          
      --visibility <VISIBILITY>
          [default: private] [possible values: private, public]
      --chain-id <CHAIN_ID>
          [default: 196]
      --service-guide <SERVICE_GUIDE>
          Exact provider service Guide. Stored locally before broadcast
      --service-guide-hash <SERVICE_GUIDE_HASH>
          SHA-256 of the exact service Guide when supplied by the provider
      --guide-consent-json <GUIDE_CONSENT_JSON>
          User-confirmed values for the matching Guide
  -h, --help
          Print help
```

## onchainos agent subscribe-device-update
```
Overwrite the receive-device list for one or more subscriptions (batch). The passed list wholly replaces the stored list; empty/omitted clears it

Usage: onchainos.EXE agent subscribe-device-update [OPTIONS]

Options:
      --job-id <JOB_ID>            Subscription jobId to overwrite (Form A, single subscription)
      --chain <CHAIN>              Chain: ethereum, solana, base, bsc, polygon, arbitrum, sui, etc
      --device-list <DEVICE_LIST>  Comma-separated device ids (Form A); empty/omitted clears the list
      --items <ITEMS>              JSON array of {jobId, deviceList} (Form B, batch). Mutually exclusive with --job-id/--device-list
  -h, --help                       Print help
```

## onchainos agent subscribe-offline-update
```
Set a subscription's offline-receive flag (0 = keep backlog, 1 = discard backlog)

Options:
      --job-id <JOB_ID>  Subscription jobId whose offline-receive flag is being set
      --chain <CHAIN>    Chain: ethereum, solana, base, bsc, polygon, arbitrum, sui, etc
      --flag <FLAG>      Offline-receive flag: `0` keeps the backlog, `1` discards it

```

## onchainos agent apply
```
Provider applies for a task (apply API → sign → broadcast)

Usage: onchainos.EXE agent apply [OPTIONS] --token-amount <TOKEN_AMOUNT> --token-symbol <TOKEN_SYMBOL> --agent-id <AGENT_ID> <JOB_ID>

Arguments:
  <JOB_ID>  

Options:
      --token-amount <TOKEN_AMOUNT>  Negotiated token amount. **Required**; must be > 0 (empty / 0 = apply for free, irreversible — CLI rejects)
      --chain <CHAIN>                Chain: ethereum, solana, base, bsc, polygon, arbitrum, sui, etc
      --token-symbol <TOKEN_SYMBOL>  Actual task currency (USDT / USDG); read from negotiation context, do not assume USDT
      --agent-id <AGENT_ID>          
  -h, --help                         Print help
```

## onchainos agent deliver
```
Provider submits deliverable (submit API → sign → broadcast)

Usage: onchainos.EXE agent deliver [OPTIONS] --agent-id <AGENT_ID> <JOB_ID>

Arguments:
  <JOB_ID>  

Options:
      --file <FILE>
          [default: ""]
      --chain <CHAIN>
          Chain: ethereum, solana, base, bsc, polygon, arbitrum, sui, etc
      --deliverable-text <DELIVERABLE_TEXT>
          Text deliverable content for auto-save. When non-empty and --file is empty, the CLI writes this to a temp file and persists it as a text deliverable [default: ""]
      --agent-id <AGENT_ID>
          Provider agentId (required). Beta backend rejects empty agenticId header → 3001 auth fail
  -h, --help
          Print help
```
