# P0-04 用户旅程（Buyer / ASP）与提升预期

> 状态: v0.1（2026-09-03）。对应 01 节点清单 / 02 信号 schema / 03 policy 配置。
> 提升估算为"量级预估"，P0 实测基线后替换为实测差。协议层/链上延迟/LLM 内容质量不在提升范围。

## 1. 与官方客户端的差异（已从代码验证的基线）

官方每事件处理链: CLI 注入 KB 级 playbook → agent 读参考文件（订阅信号单文件 25.7KB；okx-ai references 合计 428KB）→ LLM 分类/决策/翻译渲染 → 执行或询问。单次任务全流程 8-12 个 LLM 回合，每回合过路由表 + 语言锁翻译。

优化后: 同一事件 → policy 引擎（信封校验→规则→执行桥），auto 路径 0 个 LLM 调用、本地毫秒级决策；ask 路径一次确认。

| 维度 | 现在（官方客户端） | 优化后 | 量级 |
|---|---|---|---|
| 订阅信号事件 | 5-15K tokens + 2-4 次 LLM（10-40s） | auto: 0 token 本地决策；ask: 一次确认 | token 降 1-2 个数量级 |
| 单次任务全流程 | 8-12 个 LLM 回合 | 3-5 个语义节点(llm+ask)，机械节点全 direct | 回合数减半以上 |
| 确定性 | 每一步都有 LLM 幻觉面 | deterministic 部分幻觉归零；幂等 latch+journal 防漏防重 | 事件不错不漏 |
| 接入成本 | 维护会走状态机的 agent，调试以天计 | 默认配置+模板+hook 示例，小时级 | 天 → 小时 |
| 定制 | 买家仅 consent 三件套+金额上限 | 每节点/每事件可配 + script 出口 | 从"能否自动"到"每环节自定" |

边界: 内容质量、链上/API 延迟、CN 网络不变。

## 2. Buyer 旅程

### 2.1 接入（~10 min，一次性）
装客户端 → 钱包登录+身份注册（官方链上）→ 全局默认（未知事件=ask）→ 接通知通道。

### 2.2 订阅信号 ASP（3-5 min）
1. ASP 卡片: 信号模板 / schemaMode(strict|loose) / 字段覆盖 / 评分 → "可自动执行程度"直示
2. 配置向导: 解析模式 → 执行模式(全自动/半自动/人工) → 上限(每笔/每日, per venue) → 资产白名单 → 一次性确认(consentSnapshot)
3. 创建订阅（一次链上）

### 2.3 日常（按画像）
- 全自动: 信号→落盘校验→strict 解析→规则+上限→执行桥(幂等)→通知收尾。异常(字段缺/超限/余额不足)才打扰
- 半自动: 卡片"信号: buy XXX 5%, 执行/忽略/改"→一次确认→执行
- 纯人工: 只收通知
- 安全告警: SECURITY_ALERT→规则/脚本自决(如 rug_pull+持仓超阈值→紧急赎回脚本)→通知结果。LLM 只分类, 钱的动作在买家脚本

### 2.4 管理
执行日志(信号原文+信封+决策+receipt 每笔可审计) → 暂停/调上限/拒收本期 → 续订(默认 ask, 可配 auto) → 争议(LLM 起草证据, 人工确认)

### 2.5 单次任务
自然语言需求 → LLM 转任务卡(目标/预算/期限/验收) → 确认 → 上链 → 交付 → LLM 初检+确认 → 完成/拒收/争议

## 3. ASP 旅程

### 3.1 接入（30-60 min）
注册 ASP 身份+声明服务（官方）→ 声明 signalProfile(模板/字段覆盖/schemaMode) → 信号生成器脚手架（内容缝=ASP 自己的数据源+LLM/脚本 → 填模板 → 字段自检 → 交付）→ 质量门 hook 示例 → 业务 hook（订阅创建时触发预置脚本）

### 3.2 接订阅
SubAspSelected → 默认卡片(接受/拒绝), 可配 auto 自动接(能力自检)；on_request hook 自动预置

### 3.3 每期交付
内容缝生成信号 → 协议 direct 交付(幂等) → post hook 记账/通知。状态/期限/续订/回款(SubRenew/SubCompleteNotify)全自动

### 3.4 异常/争议（保留人工: 钱与声誉）
拒收(SubUserReject) → LLM 起草回应(退款/换期/争议)→确认；任务被拒 → 仲裁/退款；争议证据 LLM 起草+确认

### 3.5 运营
收入自动记账；结构化是卖点: strict 交付进买家 trustAsps + auto 授权 → 转化率。看: 订阅转化/拒收率/争议率

## 4. 一句话

- 买家: 从"每件事盯着 agent 做对"→"配一次, 只在真需要时出现"
- ASP: 从"运维一个会走流程的 agent"→"写好内容, 流程交给引擎"
- 提升最陡: 订阅信号等高频确定性流程（数量级）; 最不陡: 内容质量/链上速度（不变）
